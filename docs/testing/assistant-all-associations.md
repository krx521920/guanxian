# 助手默认全协会只读查询

## 行为与边界

- 经服务端核验的 `SYSTEM_ADMIN` 未选择管理协会时，可以直接提问、流式聊天和使用只读业务工具，查询范围为全部协会。
- 选定协会后继续按已核验的协会范围查询；请求正文不能另行指定协会来覆盖当前上下文。
- 普通协会、企业和观察员账号保持原有授权，缺少绑定的普通账号仍拒绝查询。问题中写“全部协会”不会提高权限。
- 移除要求先选协会的提示和输入禁用。浮动窗口及业务查询结果标明全协会范围；范围变更会清除旧对话、草稿和选择对象。
- 发布状态、软删除、私有文档可见性、结果数量和模型数据出站限制继续生效。全协会的系统管理员沿用其已有私有资料管理权限，不向普通账号开放私有资料。
- 查询范围不等于写入授权；不改变新增、导入、审核或写操作的权限/归属要求。
- 全协会与单协会会话使用不同记忆键。检索和模型执行审计沿用已有可空的 `association_id`，无需数据库迁移。

## 自动验证

- `AssistantControllerScopeTest`：全协会普通及流式入口、正文覆盖拒绝、未绑定普通账号拒绝。
- `PlatformAssistantServiceTest` / `PolicyRagServiceTest`：开关模型两种路径、已发布跨协会证据、私有资料隔离、范围记忆分离。
- `AssistantBusinessResultsTest`：本地无模型查询的全协会回执；范围描述不再误识别为企业关键词，文字不改变账号权限。
- `AssistantToolCallingIntegrationTest`：真实 Spring AI 工具回调链的单协会/全协会流式结果及敏感字段脱敏；模型为进程内测试替身。
- `PostgresAssistantAllAssociationsIntegrationTest`：临时真实 PostgreSQL 中的跨协会查询、草稿/软删除排除、普通账号隔离和空协会审计持久化；无真实模型出站。
- `assistant-workspace.spec.ts`：未选择时可提交、提示消失、请求不指定协会、范围切换清除旧内容。
- CI 要求新增 PostgreSQL 测试实际执行，不允许跳过后视为发布检查通过。
