# 游客公开端发布记录

## 范围与默认行为

本候选版基于 `main` 的 `0ca6d4e7fac61b952dcfbcff336a992e92c9eab7`，在独立分支 `codex/guest-public-release` 整合。仅迁移统一入口、企业负责人邀请/绑定、“我的企业”、草稿审核授权发布、游客目录及相关测试；没有迁移个人模型设置、聊天结果卡片和未合并的聊天增强。

- 统一入口 `/login`（根路径别名）；游客目录 `/public`，不要求登录。
- 企业公开字段仅限名称、类别、简介、技术能力、产品、服务、应用场景、公开版本标识与发布时间。
- 企业负责人保存草稿 → 提交 → 独立管理员审核 → 企业负责人明确授权该版本 → 独立管理员发布。审核通过不等于已公开。
- 不批量公开既有会员，不根据旧 `ACTIVE` / `PUBLIC` 自动公开。未完成授权发布时目录为空是安全的预期行为。
- 待审改动不覆盖旧游客快照；撤回、企业停用/删除/归属变化或协会停用会下架，恢复不会重新公开。
- 不新增匿名附件、政策库、聊天或内部业务接口权限；自由文本仍须人工核对是否含敏感内容。

## 迁移与验证门槛

本候选版包含 `V25__enterprise_owner_invitations.sql`、`V26__enterprise_profile_workflow.sql`；不包含尚未发布的个人模型 `V24`。Flyway 允许版本间空档；将来整合个人模型功能时，必须把其未执行迁移改为当时主干之后的新版本，不能打开 out-of-order 绕过校验，也不能修改已执行迁移的内容。

- `ProfileWorkflowPostgresTest` 在真实 PostgreSQL 上执行完整 Flyway 迁移、审核发布和生命周期下架触发器。
- `EnterpriseInvitationPostgresTest` 验证真实数据库的邀请、绑定及失效约束。
- CI 的 server job 会检查两份报告均实际运行且无失败、错误、跳过。缺少 Docker 不能冒充通过。
- `guest-publication.spec.ts` 在隔离 E2E 拓扑上使用真实 Keycloak 浏览器登录、真实业务 HTTP 和 PostgreSQL，验证三个身份、退回反馈、审核/授权/发布分离、公开字段白名单、旧快照隔离与撤回。硬限制本地 `127.0.0.1:18082`，不得指向生产站点。
- 22 个界面夹具测试验证入口、权限提示、审核流程、手机布局以及返回按钮和头像菜单；这组测试不替代真实身份/数据库验收。

## 部署前检查

1. CI 全部必要检查通过；核对远端最新 main，确认没有夹带其他分支或未提交文件。
2. 核对服务器 checkout、部署镜像、配置健康状态。注意：本候选基线 main 包含已经合并的 Chat Agent PR #4；线上镜像仍旧时，全量更新会包含该已合并代码，不能把“代码合并”当成“已部署”。
3. 创建生产业务库与 Keycloak 新备份，保留受保护原件；不得借机导入演示数据或批量授权真实企业。
4. 使用既有 `guanxian-maintain` 的固定维护命令更新确定提交、构建、启动；不修改 SSH/sudo 权限，不重建部署密钥，不执行 `down -v`。
5. 部署后匿名校验 `/public`、公开目录、未发布详情 404 和内部 API 401，检查 no-store、TLS、容器健康及实际部署版本。全部通过后才记录上线完成。

当前是发布候选记录，不是生产上线证明。CI、备份与部署结果需回填后再交付正式上线结论。
