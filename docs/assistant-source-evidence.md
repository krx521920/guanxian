# Chat Agent：可核对的招采与活动资料

## 本轮边界

读取已经入库且当前身份有权查看的 `platform_source_record`。不重新爬网、不写企业、供需或协作业务记录；不更改账号、发布授权、导入数据或数据库结构。

新增工具：

- `search_tender_evidence`：招标采购、候选、历史结果；不是平台合作需求。
- `search_activity_evidence`：公开活动、报道及企业自述；不是平台确认合作。
- `read_source_evidence`：使用实际查询返回的 UUID 重新读取单条资料；不访问外部 URL。

HTTP 资料目录与工具共用 `SourceDirectoryService` 的协会/角色校验、关联业务可见性检查和字段白名单。普通企业账号按既有资料目录规则读取所属协会允许的公开来源资料；不因此获得其他协会权限。未限定协会的系统管理员可查询全部授权协会。工具参数不接受账号、角色或协会覆盖。

## 查询及日期规则

每页最多 5 条，凭据分别显示真实总数和当前页条数。关键词是一个连续子串，不伪装成多条件语义匹配。支持不限日期、近 30 天、近一年和自定发布日期区间。相对日期以北京时间计算，含起止日；近 30 天为今天及之前 29 天。开启日期条件时，缺失或无效日期排除，不根据抓取日、导入日或活动日猜测发布日期。

来源公开证据覆盖原始快照中的对应显示字段，保留元数据更正和原始资料可核对。记录状态、企业角色、项目总金额与企业份额分开表述；不能据此断言现时可投标、具有投标资格或已发生合作。

## 模型关闭时

仍支持直接只读查询，例如：

- `查询近一年“管线监测”招标资料`
- `查询近期企业活动`
- `查询“企业全称”招标和活动资料`

页面明确标记本地业务查询，未调用大模型。复杂日期、多关键词、未可靠识别的企业条件会要求澄清，不偷偷删掉条件。只自动展示第一页；更多记录可进入对应资料目录分页查看。已选企业的追问仍遵循原有企业预检流程，不能把选择对象自动解释成招采角色过滤。

## 可核对与防护

服务器产生结构化凭据，模型文字不能生成卡片。卡片包含实际筛选、查询时间、来源编号、证据编号、核验截至日期、原文与补充依据。HTTP(S) 链接校验拒绝凭据、脚本、文件协议和混合多 URL。打开新窗口使用 `noopener noreferrer`。

“重新核对资料”重新发起受当前身份限制的 HTTP 请求；资料删除、权限收回或请求失败时清空旧详情，不将失败说成无数据。历史聊天卡片仍明确是当时的查询快照，不代表实时复核。

单轮工具总预算仍为 8 次；查询只读事务超时 10 秒，分页有上界。失败、无权限、条件无效、资料不可用和成功但为空分别返回。

## 验证层级

- Java 单元测试：实际 Spring AI 工具参数转换和服务端上下文传递（同步/流式），模型本身使用进程内替身，未调用付费模型。
- Docker PostgreSQL 集成测试：权限隔离、白名单、日期、分页、原始数据不变、移除后重读，以及模型关闭时的真实查询流。
- 浏览器组件测试：使用明确标记的模拟接口验证卡片、链接安全、失效重读、窄屏布局。
- 真实浏览器端到端测试：隔离 OIDC + Nginx SSE + PostgreSQL 中的专用合成夹具；不拦截业务 API，不连接生产。

这些验证不能替代各厂商真实模型的回答质量验收；本轮不宣称实时全网检索、全量年度覆盖或资质自动核验。
