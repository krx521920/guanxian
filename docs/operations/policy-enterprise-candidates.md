# 政策证据、自动企业候选与适用性检查

## 本次行为

1. 政策标准页自动加载候选总览：每页对比可见政策与当前范围企业，不必管理员逐对选择。不持久化“已适用”关联、不自动审核、不发送通知。
2. 政策详情列出全部候选（分页）、共同业务主题、政策/企业命中字段、详情入口及缺失证据。
3. 管理员主动生成分析时优先使用已归档原文；没有原文但有摘要时生成摘要参考分析，保留来源 URL、原始摘录、政策/企业版本及生成时间。没有摘要或原文时拒绝生成。
4. 摘要参考分析禁止通过审核，允许退回。原文归档后重新分析可升级；审核前再次检查政策/企业版本及原文片段是否仍有效。数据库也禁止 SUMMARY_REFERENCE 变成 APPROVED。
5. 同协会管理员可从候选卡片点击“以此企业准备分析”，确认框固定带入该企业和政策；再次确认才创建记录，不默认批准，不发通知。企业身份、外协会共享政策不会显示此写入入口。关闭/切换身份后丢弃旧响应；已提交到服务端的请求不会因关闭窗口而撤销。

原文关联现在要求标题匹配；政策已有来源 URL 时还必须来源 URL 相同。只有唯一的已发布、当前版本 READY 文档可作为证据；同名异来源、多个候选文档或空白片段均不能冒充已归档正文。关联不明确时退回可追溯摘要参考，而不是任选第一篇。审核时同时核对片段 ID 与留存摘录内容，ID 不变但内容变更也必须重算。

## 接口和身份边界

- GET `/api/v1/policy-enterprise-candidates?q=&page=0&size=10`：每页最多 20 条可见政策，只对其中已发布且未停用政策计算。visiblePolicyCount 包含当前可见草稿，不能当成“已发布数量”。
- GET `/api/v1/policies/{id}/enterprise-candidates?q=&page=0&size=20`：查询单条政策的候选企业，名称筛选，最大页大小 100。
- 协会人员只能匹配本协会正常企业，企业身份只匹配自己。SYS 未选协会时按每条政策所属协会计算，已选协会/企业则严格遵从该范围。
- 看得到外协会公开或共享政策不等于能看对方会员，目标企业仍受身份约束。停用协会不参与，企业须 ACTIVE、未删除。游客/观察员不能调用。
- 创建、重算、审核仍使用已有政策影响分析接口及管理员权限，不向企业开放写入影响结论的权限。
- 证据随分析及审计历史保存；旧记录保持旧算法标记，不批量改写旧结论。

## 规则和证据含义

具体领域采用有限同义词表，每个主题只计一次；企业名称及管线/管道/安全/数据/施工等泛词不单独形成候选。支持直接否定词和 ASCII 缩写边界，不声称拥有完整语义理解。

当政策与企业均有明确行业线索（燃气、供水、排水污水、供热）且无交集时，不因共同出现“监测”等词形成候选。通用设备供应商没有登记行业不算冲突，多行业企业存在共同领域仍保留。候选与分析共用该规则。企业业务角色参与线索判断；合作需求不当作企业现有能力。

分析关注程度：零主题交集为 LOW，一个主题为 MEDIUM，有原文且至少两个主题才为 HIGH。义务词不增加分值，只有摘要最高 MEDIUM。来源标记已失效或尚未到所载施行日期时降至 LOW。这是关注线索，不是法律影响或适用性结论。

角色明确不同的企业（例如政策约束运营企业，资料只表明设备制造）保留为间接业务线索、最高 MEDIUM；政府职责也不产生企业 HIGH 义务结论。候选先区分时间/主体角色线索，再按主题数排序。总览仍为政策分页，并非跨全部政策的全局排名。已失效和未来施行的提示同时出现在总览和详情。

返回适用对象、地区、效力与时间、义务与机会四组检查：
- 政府职责不直接转成企业强制义务；区分合规措辞、业务机会、混合线索。
- 可识别的运营、建设业主、施工、设计勘察、设备制造、检测监测角色在实际企业资料中对比；匹配只说明存在角色文字线索，不证明资质或实际项目职责。无角色信息仍为待核实。
- 否定措辞不当作正向要求/机会；推荐性条款不覆盖另一条独立义务。“未废止”和“部分条款废止”不等于整部政策失效。
- 不能把公司名称或注册地址当作项目所在地，企业实际角色、项目、资质缺失时明确待核验。
- 已到施行日期不等于今日现行有效。页面不再根据日期显示“现行有效”。
- 导入适用对象等字段仅在标题、摘要、来源 URL、分类、级别、施行日期、标签仍与来源快照一致时使用，避免引用失效元数据。
- applicability 始终是 UNVERIFIED。没有联网核验政策现行效力，也不向外部模型发送企业资料。

## 性能与时效

候选即时读取、不持久缓存；更新资料后刷新/重新进入即可重算。前端身份/协会/企业变动立即清空结果，丢弃旧响应；无关身份对象刷新不重复请求。

总览使用一次批量来源元数据读取和共享企业读取，不随政策数产生 N+1 请求。每次最多扫描 2000 家；超限显示截断提示及实际扫描数量，单政策详情可按企业名称缩小范围。跨多个协会时此上限为合计，不是每协会 2000 家。排序不代表概率或经过验证的准确率。

## 发布与回滚注意

- 新增 V31：可空 evidence_details、证据类型约束、摘要不可审核约束及来源查找索引。不是生产数据补写脚本，不需重新导入 ZIP。
- 必须先备份并通过 PostgreSQL 集成测试，再按现有发布流程部署服务端和前端。
- 旧后端不可直接回退使用：它不理解摘要记录，可能把零原文的摘要结果视作普通待审核分析。需要回退时，应先评估/隔离新建的摘要分析；不能为回退删除真实企业、政策或账号。
- 不修改用户先前指定的回滚标签。上线按独立 PR、完整 CI、备份和受控维护工具执行；不附带数据导入或自动审批。

## 验证边界

有候选不等于适用；零候选不等于无关。需人工抽样核对误报/漏报和真实适用条件后才能评价匹配准确率。
自动候选总览与主动创建“待核实分析”是两个行为，不能把候选数量当成正式分析数量。
数据库集成测试若因 Docker 不可用而 skipped，不视为通过；CI 将候选、影响分析、升级兼容三套 PostgreSQL 测试列为不可跳过的发布门禁。
