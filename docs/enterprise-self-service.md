## 企业用户可以做什么

- `/enterprise/catalog`：我的供需。后台按当前绑定企业筛选产品、服务和需求，在 SQL 分页与计数之前收窄范围。负责人沿用现有草稿、提交、审核、停用、关闭与恢复草稿流程；普通成员只读。审核仍由协会负责，供需不会自动进入游客端。
- `/enterprise/cooperation`：我的合作。以“合作机会与邀请”“协作进展”组织现有匹配、邀请应答、洽谈、反馈和协作能力。复用已有后端参与方/状态/版本权限，不增加跨企业或游客权限。
- `/enterprise/team`：企业团队。仅企业负责人访问，不能使用系统代管上下文。团队新增成员固定为 `ENTERPRISE_MEMBER`，无自助角色选择或晋升。
- 企业工作台提供三个快捷入口，企业导航收拢重复的供需、匹配与协作菜单；原地址保留，协会端不改变。

## 团队邀请与停用

1. 同事先由系统管理员建立统一认证账号；这里不创建 Keycloak 用户、设置密码或自动发送邮件。
2. 负责人输入指定账号名，系统从后台绑定确定企业，生成 72 小时一次性展示链接。客户端不能指定企业或目标角色。
3. 同事登录、确认只读权限申请；系统管理员在原邀请核验页面查看申请角色并独立审核。负责人不能审核自己的团队申请。
4. 审核成功后写入应用账号绑定和精确版本的普通成员授权；下一次读取身份即可进入工作台。此权限不包含 `ENTERPRISE_WRITE`、`MEMBER_REVIEW` 或 `ACCESS_BINDING_WRITE`。
5. 负责人只能停用本企业、通过此流程开通且绑定仍一致的普通成员，不能停用自己、负责人、其他企业账号或已经变更归属/授权的账号。必须提供当前 `If-Match` 与原因；停用和审计同事务，历史业务数据保留。

已有账号不会被团队邀请覆盖或自动重新激活。恢复、离职交接、负责人变更和既有账号角色调整仍需系统管理员核验；本阶段没有企业自助恢复/删除账号功能。

邀请人的账号停用、subject 撤销或绑定版本变化会使尚未完成的成员邀请失效。成员授权每次请求检查账号、企业、协会、审批与精确绑定版本，停用后后续业务请求被拒绝。已加载在浏览器中的内容不会被远程擦除。

## 后端接口

| 接口 | 范围与行为 |
| --- | --- |
| `GET /api/v1/offerings?ownOnly=true` | 当前企业；同一过滤条件用于列表和总数，非企业身份拒绝 |
| `GET /api/v1/demands?ownOnly=true` | 同上，原有可见范围与删除状态校验继续生效 |
| `GET /api/v1/my-enterprise/team/members?page=0` | 负责人查看本企业工作流开通成员，每页 20 条 |
| `GET /api/v1/my-enterprise/team/invitations?page=0` | 负责人查看本企业普通成员邀请，不返回邀请凭证/claim subject |
| `POST /api/v1/my-enterprise/team/invitations` | 仅接收 username，固定普通成员，只返回本次邀请凭证 |
| `PUT /api/v1/my-enterprise/team/invitations/{id}/revoke` | 归属校验和强 If-Match；不能借此撤销已开通身份 |
| `PUT /api/v1/my-enterprise/team/members/{id}/disable` | 归属、当前授权、强 If-Match、停用原因、原子审计 |

团队响应 `Cache-Control: no-store`。列表不返回邮箱、密码、私钥或外部身份凭证。游客 API 与发布快照完全未改。
