# 游客、企业与协会权限及公开字段基线 v1

日期：2026-09-05。

范围：完成开发顺序中的第一步——确定游客看什么、企业改什么、谁负责审核。
本文是后续实现的约束，不是已经上线的权限配置。本轮只新增文档，不修改接口、账号、数据库或线上服务。
现状依据为当前本地工作树源码，不代表生产环境已部署相同版本。

## 1. 确定的产品边界

1. 游客无需登录，只读浏览经过审核、明确同意公开的资料；不把现有登录态 `OBSERVER` 当成游客。
2. 企业管理员管理本企业资料，通过草稿和审核更新；企业普通成员第一阶段不具备企业资料编辑权。
3. 协会运营整理、导入、协助企业修改和检查完整性；协会管理员承担本协会资料的最终审核。
4. 发布到互联网是独立动作，不由 `ACTIVE`、会员身份或旧 `visibility=PUBLIC` 自动触发。
5. 已有或后续导入的企业记录默认不对匿名游客公开。导入数据不等于创建登录账号，也不等于取得公开授权。
6. 前端身份入口只影响导航。角色、协会归属、企业归属必须由后端验证，不能由登录选项、请求参数或 Chat Agent 决定。

## 2. 身份和操作权限

以下均为目标规则。每项授权同时检查角色、所属协会/企业、资源状态、字段范围；隐藏按钮不能替代后端检查。

| 身份 | 可以看什么 | 可以做什么 | 明确禁止 |
| --- | --- | --- | --- |
| 游客（匿名访问者） | 已发布企业公开卡片、详情和明确公开的政策内容 | 搜索、筛选、阅读；打开登录入口 | 任何业务写入；内部联系人、未发布资料、批量导出、审核、管理后台 |
| 登录观察员 `OBSERVER` | 授权范围内的只读目录及明确授权字段 | 内部只读查询 | 编辑、审核；仅因拥有 `MEMBER_READ` 就读取私人联系方式 |
| 企业管理员 `ENTERPRISE_ADMIN` | 本企业资料、草稿、审核结果；其他企业的公开或明确共享字段 | 编辑本企业草稿、提交审核、申请身份资料更正、申请发布；撤回本企业公开展示 | 编辑其他企业；自我审核；自行改变角色、协会归属、审核状态 |
| 企业成员 `ENTERPRISE_MEMBER` | 本企业获准共享的业务资料、公开资料 | 第一阶段只读；后续单独授权产品、需求等操作 | 默认编辑企业主档、管理账号、读取未授权联系人、审核 |
| 协会运营 `ASSOCIATION_OPERATOR` | 本协会履职所需资料和待处理任务 | 整理、导入、协助填写草稿、检查材料完整性 | 最终审核、直接发布、跨协会处理、自行分配角色 |
| 协会管理员 `ASSOCIATION_ADMIN` | 本协会企业、审核材料及相关审计记录 | 核验企业归属，审核修改，确认公开版本、退回、下架 | 审核自己提交或修改的同一版本；跨协会越权 |
| 系统管理员 `SYSTEM_ADMIN` | 按明确选择的管理范围访问；必要的账号和运行信息 | 管理绑定与平台配置；异常下架；在明确协会范围内承担独立复核 | 无痕代改、自动绕过发布授权、用系统身份自审自发 |

补充约束：

- 企业管理员也不能默认读取其他企业内部联系人、认领材料、审核意见或私有附件。
- 内部联系方式默认仅本企业管理员、承担该企业管理职责的协会人员以及有明确事由的系统管理员可读；企业成员或观察员需要单独授权。
- 友好协会共享沿用独立的合作授权和字段约定，不因游客上线扩大共享范围。
- 账号绑定第一阶段由系统管理员执行，协会管理员核验并提出绑定申请；不能把“审核资料”权限当成“分配身份”权限。
- 邀请/认领已有企业须核验申请人与企业的关系，再绑定已有企业 ID；名称相同、知道企业 ID 或知道联系人号码都不足以自动认领。
- 首阶段一个账号绑定一个企业。多企业账号、团队细分权限后续另行设计，不通过前端下拉选择获得权限。
- 会员资格、活动参会状态、企业账号权限分别管理；参会不自动成为会员或获得企业管理权。

## 3. 游客公开字段白名单与企业编辑规则

游客接口使用独立公开 DTO，只从审核发布的快照取值，不直接序列化当前 `MemberProfile` 或 `MemberListItem`。
下表覆盖当前 `MemberProfile` 的全部 23 个字段；新增字段默认不公开，必须更新这份清单并经过评审。

“可公开”表示发布版本可以包含，不表示数据库中同名字段现在就能向游客返回。
“普通草稿”表示本企业管理员可编辑，协会运营可在授权范围内协助；提交后均需审核。

| 现有字段 | 游客公开规则 | 企业管理员修改规则 | 审核或控制责任 |
| --- | --- | --- | --- |
| `id` | 可公开，作为详情标识；不是访问凭证 | 不可修改 | 系统生成；按 ID 查询仍须检查发布资格 |
| `associationId` | 不返回内部归属 ID；另提供获准公开的协会显示名称 | 不可修改 | 归属调整走管理核验与绑定流程 |
| `name` | 可公开已审核名称 | 只能提交名称更正申请，不能直接覆盖正式名称 | 协会管理员核验证明；判断是否为同一法人主体 |
| `unifiedSocialCreditCode` | 首版不公开 | 只能提交身份资料更正申请 | 协会管理员核验；不得借此把账号转给另一主体 |
| `category` | 可公开已审核行业分类 | 普通草稿 | 协会管理员审核 |
| `address` | 不公开原始详细地址 | 普通草稿，内部资料 | 协会管理员审核；不能直接截取作为公开地址 |
| `contactName` | 不公开内部联系人 | 普通草稿，内部资料 | 协会管理员按职责核验，限制读取范围 |
| `contactPhone` | 不公开内部手机号/电话 | 普通草稿，内部资料 | 协会管理员按职责核验，限制读取范围 |
| `contactEmail` | 不公开内部邮箱 | 普通草稿，内部资料 | 协会管理员按职责核验，限制读取范围 |
| `introduction` | 可公开已审核简介 | 普通草稿 | 检查真实性、个人信息和不应公开的内容 |
| `capabilities` | 可公开已审核能力标签 | 普通草稿 | 协会管理员审核，不暗示第三方能力认证 |
| `products` | 可公开已审核产品描述 | 普通草稿 | 协会管理员审核；不自动公开独立产品记录或附件 |
| `services` | 可公开已审核服务描述 | 普通草稿 | 协会管理员审核 |
| `applicationScenarios` | 可公开已审核应用场景 | 普通草稿 | 协会管理员审核 |
| `cooperationNeeds` | 首版不公开原始合作需求 | 普通草稿，内部业务资料 | 协会管理员审核；公开需求以后走单独发布流程 |
| `visibility` | 不返回内部可见性配置 | 不可直接修改；仅提出公开申请 | 协会管理员确认共享范围；不能替代发布授权 |
| `status` | 不直接公开内部状态；仅展示明确的公开审核说明 | 不可修改 | 审核/停用流程控制；不与会员或参会状态混用 |
| `version` | 不返回内部编辑版本 | 不可修改 | 服务端并发控制；公开缓存使用独立发布版本 |
| `createdAt` | 首版不公开原始创建时间 | 不可修改 | 系统维护 |
| `updatedAt` | 不公开原始更新时间；另展示公开版本发布时间 | 不可修改 | 系统维护，避免泄露待审核修改时间 |
| `deletedAt` | 不公开；已删除企业不能再提供公开详情 | 不可修改 | 受控删除/下架流程 |
| `deletedBySubject` | 不公开操作者身份 | 不可修改 | 系统审计；限制管理人员读取 |
| `statusBeforeDelete` | 不公开内部恢复信息 | 不可修改 | 受控恢复流程，恢复不自动重新发布 |

首版允许的现有字段只有：`id`、`name`、`category`、`introduction`、`capabilities`、`products`、`services`、`applicationScenarios`。

需要新增或派生的公开信息，不冒充现有字段：

- 协会显示名称：由服务端提供获准公开的名称，不接受浏览器指定归属。
- `publishedAt`：当前公开版本的发布时间，不能用原始 `updatedAt` 代替。
- 审核说明：使用“资料已审核”，不把当前 `ACTIVE` 显示成官方资质认证、会员资格或参会证明。
- 后续可增设 `publicRegion`（企业确认的市/区）、专门的对外联系方式、网站及 Logo。首版不要求这些字段；不从私有地址、联系人或私有附件自动回填。
- 若未来增加会员/参会徽标，必须分别关联实际资格与活动记录、有效期和公开许可。

公开白名单并不能防止简介中夹带手机号或合同信息。发布前必须提供游客视角预览，记录企业授权范围，并人工检查自由文本与图片；内容扫描只能辅助，不能代替审核。

## 4. 修改、审核与发布流程

推荐流程：

`编辑草稿 → 提交不可变版本 → 协会运营检查（可选） → 协会管理员终审 → 明确公开授权 → 发布该审核版本`

退回流程：`退回并说明原因 → 企业修改新草稿 → 重新提交`。

具体规则：

1. 保存草稿仅更新草稿；提交审核后冻结该版本。再次修改形成新版本，不能悄悄更改正在审核的内容。
2. 审核通过可更新内部正式资料，但不自动发布到互联网。企业确认公开字段/版本并授权后，管理员才能发布对应审核快照。
3. 已公开企业修改资料时，游客继续看到上一份已发布版本；审核通过且满足发布条件后才切换。待审内容不参与公开搜索、排序或统计。
4. 名称/信用代码更正走身份核验。若实际是另一法人主体，不能直接替换原主体，应另建企业并走受控绑定流程。
5. 最终审核人不能是该版本的提交人或编辑人。协会人员代填也必须留下实际编辑人；没有独立审核人时等待分配，不能自动跳过。
6. 退回、停用、下架及紧急处置必须填写原因。记录提交人、编辑人、审核人、版本、字段差异、公开授权、时间和结果。
7. 企业管理员撤回本企业公开展示应立即停止公开访问并记录审计；不必等待重新审核。管理员因泄露或冒用等问题可紧急下架。
8. 企业/协会停用、企业删除、公开授权撤回、公开版本下架，均立即取消该资料的公开资格；恢复主体或账号不自动重新发布。
9. 下架需同步处理公开搜索、缓存、附件访问和 AI 检索资格。以前已被用户下载或复制的内容无法承诺从外部追回。
10. 发布、审核、撤回均做服务端版本校验；并发冲突应提示重新查看，禁止后提交者无提示覆盖。

需要拆开的状态轴：企业经营/系统可用状态、会员资格、活动参会状态、修改审核状态、公开发布状态。账号启用状态另行管理。
不能继续用一个 `MemberProfile.status` 同时代表这些含义；正常企业提交草稿不应因此从匹配等内部业务中消失。

公开资格判定基线：有对应版本的审核通过记录、有明确公开授权、已执行发布、企业及协会可用、未删除且未撤回/下架。任一条件不满足，游客不可访问。

## 5. 其他模块的公开边界

| 模块 | 游客第一阶段 | 企业和内部人员 |
| --- | --- | --- |
| 企业目录 | 仅公开版本白名单；分页、筛选和总数都基于公开集合 | 公开字段 + 另外授权的内部字段，不能因登录即获全部字段 |
| 政策标准 | 仅明确允许公开并审核发布的条目 | 内部文档按原有授权；上传到知识库不等于允许公开 |
| 产品与需求 | 企业资料中的已发布产品/服务文字；独立需求发布以后再做 | 按所属企业和共享规则查询、操作 |
| 资料附件 | 首版不开放内部附件下载 | 文件独立校验归属、用途及授权；以后公开文件须独立审核、扫描并明确发布 |
| 匹配与协作 | 不展示内部需求、匹配分数、合作双方确认或沟通记录 | 按业务参与方和协会职责授权，不因目录公开扩大权限 |
| 审核、审计、账号 | 不提供游客入口或数据 | 最小职责范围；企业只看自己的审核结果，不看其他企业审计 |
| Chat Agent | 首版不开放匿名业务助手；可保留静态使用说明 | 延续只读定位，使用当前用户的行级与字段级权限，不能借工具调用扩大可见数据 |

未来游客助手只能访问独立公开检索集合和公开只读工具；引用、卡片、对比、推荐、附件链接、流式输出及跨轮记忆必须一致限制。
切换身份/企业或权限被撤回后，不得继续用之前缓存的私有业务结果回答。模型服务商/API Key 选择不会增加业务权限。
不得将私有 MinIO 桶整体改成公开，也不能用一个可下载链接绕过文件授权检查。

## 7. 后续实现顺序与验收清单

不改变已确定的整体产品顺序，但必须先完成安全前置项才能公开访问：

1. 先将本清单落实为服务端字段投影、授权测试和版本数据设计；新增字段默认拒绝公开。
2. 再做统一入口及按真实身份进入对应工作台。游客入口在公开接口及版本隔离完成前，不接入内部成员数据。
3. 做企业邀请/绑定与“我的企业”；接入草稿、身份资料更正申请、审核差异与意见。
4. 完成独立审核、公开授权、发布快照、撤回及缓存/索引失效后，再开放游客展示。
5. 最后扩展企业产品、需求、协作、成员授权和公开只读助手。

| A10 | 已发布简介中混入的私人联系方式会在预览和人工审核中被发现并处理；扫描能力不能被当成绝对防泄露保证 |
| A11 | 普通已审核企业不显示虚假的会员、参会或资质认证徽标；会员/活动信息由独立来源核验 |
| A12 | 已登录观察员、本企业成员、其他企业管理员分别做字段级测试；“只读”不能绕过隐私字段限制 |
| A13 | 猜测未发布企业 ID、公开查询筛选或分页不能暴露私有记录及其数量；公开页 404 不暴露未发布原因 |
| A14 | 身份切换/撤权后，助手的工具、卡片、引用、会话记忆和导出不复用越权数据；公开文件不导致整个私有桶可读 |
