# 企业负责人邀请、绑定与“我的企业”

日期：2026-09-05。状态：本地实现和验证；未提交、推送、部署，也未创建真实账号、发送邀请或修改生产数据。

本阶段承接 `visitor-enterprise-access-policy.md` 和统一入口。优先服务已建档的企业，绑定其原有企业 ID，不重复创建企业。

后续更新：资料维护已接入独立草稿、审核反馈与发布，当前行为以 [资料草稿与审核发布](enterprise-profile-workflow.md) 为准。下方验证数量是本邀请阶段的历史记录。

## 使用流程

1. 先确认负责人已有 Keycloak 统一认证账号，并准确核对登录账号名。当前没有自动开户、密码发放、自助注册或邮件发送功能。无需向本系统提交密码或 SSH 密钥。
2. 协会管理员或系统管理员进入“负责人邀请”。系统管理员必须先选择管理协会；若选择了代管企业，只能在该企业内操作。
3. 查找已有企业，输入负责人账号名，创建邀请。72 小时有效的链接只在创建成功时显示一次，复制后通过可信渠道发给对应负责人。丢失链接须撤销原邀请后重发。
4. 负责人打开链接，使用指定账号登录。未绑定账号进入独立 `/join` 页面，不加载内部工作台、会员数据或 Chat Agent。核对企业、勾选授权确认后提交申请。
5. 系统管理员核验真实授权关系，填写核验依据或退回原因，再批准/退回。仅有姓名、企业 ID 或邀请链接不能自动绑定。协会管理员可发起、查看、撤销，但不能审核账号绑定。
6. 批准后，负责人点击“重新检查权限 / 进入我的企业”，同一有效会话即可重新读取后台权限，进入企业工作台。左侧“我的企业”与工作台“维护本企业资料”均指向 `/enterprise/profile`。
7. 负责人维护业务分类、简介、能力、产品、服务、应用场景、合作需求及内部联系资料；保存独立草稿后主动提交审核。企业成员仅查看内部生效版本。

## 已实现的安全边界

- 32 字节随机邀请凭证，数据库只保存 SHA-256；不在审计、普通列表或 `toString()` 中输出凭证。创建/预览/确认/审核响应禁止缓存。
- 邀请链接使用 URL fragment；页面读取后移除 fragment，短期保存在当前标签页的 sessionStorage 中以衔接 OIDC 跳转。凭证不放入 OIDC state/回跳地址，也不放入 API URL；预览和确认通过经认证的 POST 传递。浏览器脚本仍需遵守现有 XSS 防护边界。
- 预览/确认要求有效 JWT、准确的 `preferred_username`；确认后同时锁定 JWT subject。重复确认同一申请是幂等行为，不重复创建账号或扩大权限。过期、撤销、已审核、错误账号及重建同名但不同 subject 的账号不能消费邀请。
- 新建的是应用侧 `user_account` 绑定记录，不是 Keycloak 密码账号。停用、已撤销 subject、另一个主体占用用户名、已有其他企业/协会归属均不允许邀请覆盖。外部 subject 为空的历史本地账号仍须系统管理员通过既有绑定流程处理。
- 申请、审核、账号绑定、授权及审计在事务中完成；并发版本由强 `If-Match` 保护。失败时不留下半绑定账号。审核人不能审核自己的负责人申请。
- 新增 `enterprise_owner_grant` 只支持 `ENTERPRISE_ADMIN`，不能授予系统或协会管理员。每个 Bearer 请求检查授权记录、申请审批结果、精确账号/subject/企业/协会、绑定版本、账号和组织状态以及 subject 撤销状态。
- 已有 OIDC 角色映射继续保留；本次新增授权并不替代既有角色管理。绑定修改、停用/恢复、解绑导致版本或归属改变时，本流程旧授权失效；重新开通需重新核验。已有身份提供方角色须按既有账号管理策略一并处理。
- `GET/PUT /api/v1/my-enterprise` 的目标完全来自后台账号归属，不接受页面传来的目标企业 ID。混合管理员身份不能借系统代管上下文使用该入口。后台保留对其他旧编辑接口的归属校验，并统一禁止企业负责人直接更改名称、信用代码和协会归属。
- 企业成员的“我的企业”响应不包含信用代码、详细地址、联系人、电话和邮箱。**这不是整个旧会员模块的字段权限改造**，其他接口的字段收口仍须继续按权限基线推进。

## 本阶段未完成的能力

- 自动建立 Keycloak 用户、邮件邀请/通知、找回密码、手机号验证、人员离职交接及多企业账号。
- 企业身份资料更正申请。草稿、字段差异审核、版本授权/发布/撤回和独立游客 API 已在后续本地阶段实现，见上述说明；没有把已导入企业自动公开，也没有改 MinIO 权限。
- 自动分配平台/协会角色。系统管理员仍使用已批准的身份管理渠道管理这些角色。

## 接口与迁移

| 接口 | 权限/用途 |
| --- | --- |
| `GET/POST /api/v1/enterprise-invitations` | 指定协会范围的系统/协会管理员，分页查看与创建 |
| `PUT /api/v1/enterprise-invitations/{id}/review` | 系统管理员 + `ACCESS_BINDING_WRITE` + 强版本 + 核验说明 |
| `PUT /api/v1/enterprise-invitations/{id}/revoke` | 同范围系统/协会管理员 + 强版本，不能撤销已开通账号代替停用 |
| `GET /api/v1/onboarding/session` | 有效 JWT 的最小身份信息，停用/撤销身份拒绝 |
| `GET /api/v1/onboarding/invitations` | 仅当前 subject 的申请，最近 30 条 |
| `POST /api/v1/onboarding/preview`、`/claim` | 凭证 + 已认证指定账号；claim 需主动确认 |
| `GET /api/v1/my-enterprise` | 本企业读取内部生效资料，强 ETag，禁止缓存；旧 PUT 已拒绝，编辑使用独立草稿接口 |

新增 Flyway `V25__enterprise_owner_invitations.sql`：两张增量表，未修改既有企业、用户或密码数据。部署前必须对照最新主干确认 V24/V25 版本未被其他工作占用；当前工作树还有前序功能，不能直接整树盲目部署。
