# 统一入口与身份分流

日期：2026-09-05。实现于本地工作树，尚未推送或部署。
权限方向沿用 [游客、企业与协会权限基线](visitor-enterprise-access-policy.md)。

## 已接入的页面

| 路径 | 行为 |
| --- | --- |
| `/`、`/login` | 同一统一入口，提供企业登录、管理员登录、游客浏览；已有有效身份则进入授权工作区 |
| `/login?entry=enterprise` | 企业登录说明，继续进入既有 OIDC 统一认证 |
| `/login?entry=admin` | 管理员登录说明，继续进入相同 OIDC 统一认证 |
| `/public` | 无需登录的独立公开页面，不挂载内部侧栏、通知、账号菜单或 Chat Agent，不请求业务接口或 `/users/me` |
| `/auth/callback` | 保留既有 OIDC 回调；核验后台身份后，验证返回路径权限再跳转 |
| `/enterprise` | 已绑定的企业管理员、企业成员进入本企业工作台；显示实际绑定组织及管理/只读身份 |
| `/association` | 系统管理员、协会管理员和协会运营进入现有管理工作台 |
| `/members` | 登录观察员仍进入授权只读目录；不等同于匿名游客 |
| `/access-help` | 已验证但缺少所需协会/企业绑定的账号进入说明页，不加载业务工作台；提供重新检查、退出及游客入口 |

其他既有业务 URL 保持不变。布局父路由改为 `/workspace`，子页面使用原有绝对路径，避免与统一入口共用同一个页面容器。
返回工作台按钮、头像菜单和界面设置保留；头像菜单新增“浏览公开页面”。

## 身份核验与跳转规则

- 两个登录入口只是用途提示，不向身份提供方请求或赋予企业/管理员角色。
- 生产认证继续使用 OIDC Authorization Code + PKCE，身份取自后端 `/users/me`，不信任本地演示标志或单独读取的令牌角色声明。
- 多角色账号按已有角色清单顺序稳定选取工作区：系统管理员、协会管理员、协会运营、企业管理员、企业成员、观察员。选取范围仅限后台核验返回的角色。
- 登录返回地址须为本站路径且有对应页面权限；拒绝外站、反斜杠、控制字符，以及登录/回调等循环跳转目标。
- 允许返回原先有权限的业务深链接。无权限的地址回到自身工作台，不通过“管理员入口”或 `redirect` 提升权限。
- 企业管理员直接访问其他企业编辑地址，会在页面挂载前回到自己的工作台。服务端原有归属校验仍是最终权限边界。
- 企业账号需协会和企业绑定；其他非系统管理账号需协会绑定。未选协会的系统管理员可进入后台，继续使用原有管理范围选择。
- 若后端直接以 403 拒绝账号，登录页明确提示访问权限或组织绑定问题；不会假装认证成功进入工作台。
- 访问令牌过期清除身份时，内部页面立即隐藏并返回登录入口。账号变化时重新挂载业务页面及聊天组件，避免沿用旧账号的界面状态。
- 本地 demo 模式仍有明确测试标识；生产构建不会提供自选角色权限。

## 本次刻意没有开放的功能

公开页面已经可以独立浏览，但企业公开目录暂时只显示“公开资料尚未开放”的真实状态和使用说明。
它没有把内部企业列表改成公开 API，没有使用模拟企业伪装正式公开资料，也没有根据旧 `PUBLIC` 标志发布既有企业。
访客的“无数据”说明不代表数据库没有会员，只代表当前还没有接入经过独立审核发布的公开版本。

以下仍属于后续阶段：

1. 企业邀请/确认、核验和绑定已在后续本地阶段实现，详见 `enterprise-owner-onboarding.md`；自动开户和生产验收仍待完成。
2. 草稿、内部正式版本与游客公开版本隔离。
3. 独立审核、公开授权、发布/撤回及缓存和搜索同步。
4. 正式公开企业/政策数据接口和公开目录检索。

后续阶段已将企业工作台上的“维护本企业资料”连接到专属“我的企业”页面；企业普通成员只读。草稿隔离仍未实现。
本文件记录统一入口阶段的验证；后续邀请阶段的后端权限及增量迁移改动见 `enterprise-owner-onboarding.md`。身份提供方和生产部署配置未改动。

## 验证方式

本轮结果：333 项前端单元测试、15 项本地浏览器测试通过；生产构建、浏览器测试文件的 TypeScript 检查和改动空白检查通过。

在 `apps/web` 下运行：

```powershell
npm.cmd test
npm.cmd run build
# 有 Playwright 自带 Chromium 时无需指定 channel；也可以使用已安装的 Chrome。
$env:GUANXIAN_BROWSER_CHANNEL = 'chrome'
npx.cmd playwright test --config playwright.entry.config.ts
```

- 单元测试覆盖返回路径安全、六种角色与全路由矩阵、回调分流、跨企业编辑拦截、缺少绑定和匿名隔离。
- 浏览器测试使用真实 Vue 页面和 OIDC 客户端代码，但身份提供方及业务响应均为本地模拟；测试地址仅监听 `127.0.0.1:18188`，不接触生产服务。
- 浏览器用例涵盖桌面/手机、两个登录按钮发起相同 PKCE 认证、后台核验六种身份、缺少绑定、后端拒绝、过期登录、游客无内部请求、返回与头像菜单。
- 截图保存在 `test-results/entry-routing`，截图中的企业和账号属于测试夹具。

这些验证不等于生产 Keycloak 密码登录端到端验收。后续经批准部署时，仍需使用真实企业管理员、企业成员和协会管理员账号确认绑定、跳转及后台权限，并在无痕窗口确认游客边界。
